# Changelog

User-facing changes, newest first. Dates are release dates.

## 2026-06-20

### Features
- Added a guided edge bridge setup in Print Manager → Add a connection → "Edge adapter (your bridge)": it shows the one command to run the bridge on a box at your site, watches live for it to dial in ("Waiting…" → "Bridge online ✓"), and creates the tunnel connection once it's connected. The way to reach a LAN machine from a hosted Cobblr.
- Reach a LAN machine from a hosted Cobblr. A hosted instance (strict egress) can't dial your home network directly, so now an on-site edge bridge dials OUT to Cobblr and holds a tunnel open; Cobblr routes printer commands down it. Create an `edge_adapter` connection with a `cobblr-edge://` address and the bridge handles the rest. No inbound firewall hole, no SSRF surface (the cloud never fetches a private IP). The tunnel now powers connection-test and device-listing too, not just job send/poll.
- Read QR labels printed by another app. Configuration → External QR rules lets you teach the scanner a foreign label format (a companion app URL, a bare Homebox number, anything) and map it to the matching item here, so labels you already printed keep working without a reprint. Scan one and it opens the item exactly like a native Cobblr label; paste a sample into the built-in tester to check a rule before you trust it. Fully opt-in: with no rules, the scanner behaves exactly as before.

### Improvements
- Bambu connections now show which way they work: a "monitor only" / "control" badge with the reason (hover it), and when you add a Bambu you choose up front (Cloud account (live status, no remote control) Bambu blocks it) or LAN via your edge bridge (full control: send / pause / cancel).
- Cloud Bambu printers now show real-time status on the fleet: live nozzle/bed temps, print state, and the printer's own progress (layer + time left), streamed from Bambu's cloud MQTT instead of the slow HTTP poll. Works even for a print you started straight from Bambu Studio.
- When you add a Bambu printer and pick which one it is, the printers now show as a clickable card stack (name, model, online/offline) instead of a dropdown, and a single printer is pre-selected. Matches the look of the connect wizard.
- Adding another Bambu printer no longer asks you to sign in again. When you pick Bambu Lab, Cobblr reuses the Bambu account(s) you've already connected and lists the printers on them you haven't added yet: pick one and it links. You can connect several Bambu accounts at once (a connection is one account); when you have more than one, a small Bambu account picker lets you choose which, and + Connect another Bambu account adds a new login. Signing into the same account again refreshes that connection in place (no duplicate) so its machine links and fleet view stay intact.
- Adding a machine to a bridge you already run is now obvious: if your edge bridge is online, the setup skips the install steps and goes straight to "add a machine", so you can plug a Bambu (LAN), Prusa, Klipper, etc. into your existing bridge without reinstalling. Also: in the pool machine picker, the printer name now gets priority over the connection it's on (no more "Thum…").
- Known machines now get the right product photo. Cobblr checks a curated image catalog (the `CobblrHQ/printer-images` manifest) before its live web-image search, so a Prusa Mini stops showing up as an MK4. Fix or add a model's photo in that repo and it updates within minutes: no Cobblr redeploy.
- Hooking up a non-Bambu printer is now as slick as the Bambu wizard. Pick RepRapFirmware (Duet), Klipper, Prusa, or Marlin/OctoPrint when adding a 3D printer and a Connect directly option lets you enter the printer's address (and API key if its firmware needs one) right in the dialog. Cobblr installs the right driver, creates the connection, tests it, and links the printer. No trip to the Print Manager, no pasted JSON. The Print Manager → Drivers dialog also gained a one-click catalog for installing those drivers on their own.
- A Print history section on Digital Fabrication: at-a-glance stats (prints, success rate, filament used, print time) over a 7 / 30 / 90-day window, a per-printer rollup, and your recent prints: all from the jobs Cobblr already tracked, no new setup.
- A print-manager connection's printers now expand inline as a children list under the connection row. Click the chevron (or the row) instead of opening a separate modal. Fewer clicks, nothing pops over the page; the link-to-machine pickers are right there in place.
- Pause / resume / cancel a running print now works on OctoPrint, Klipper (Moonraker), and Duet: the live-control buttons that used to be greyed out for those managers now act. Support is declared per driver (a manifest's `commands`), so any declarative manager can add control without a code change.
- The Machines page now remembers whether you were on Items or Fleet across a refresh (a new persisted-view helper), and the fleet's live "time left" reads as 13h 2m instead of 782m.
- The edge bridge is now install-once, add-machines-anytime. Name it and Install the bridge with just a token: the box dials in and stays open. Then add machines to it whenever (in the setup dialog or later); each rides the tunnel and the running bridge configures it on the fly, no restart, no regenerated command. Naming the bridge is enough to install it; machines are step two, exactly as you'd expect.
- Installing the edge connector is a smooth in-flow step now: no trip to another page. Add a printer that's on your network from a hosted Cobblr, pick "Via an edge bridge", and the dialog: asks what it's bridging (Klipper / Prusa / Duet / Bambu-LAN / LightBurn, pre-selected from the printer kind, with the right fields), generates a least-privilege token for you (new `devices:edge` scope that can *only* run the bridge), and bakes both into a ready-to-run command. It then watches for the bridge to dial in and lets you pick the machine.
- The edge-bridge install step now offers a docker compose snippet alongside the `docker run` command: toggle between them and copy whichever fits how you run things.
- One edge bridge can now front all the machines on your site over the tunnel. The cloud routes each call to the right machine by its instance id (`/voron/devices`, `/mk4/status/…`), so a single bridge with several configured machines: Klipper here, a Prusa there, a Duet too, all reach a hosted Cobblr through one dial-out connection. Add a machine = add an instance to the bridge config + a connection in Cobblr.
- The edge-bridge setup now configures one bridge for all the machines at your site. It clearly frames the first machine, and + Add another machine lets you put several on the same bridge (each with its own driver + IP). It generates one run command and creates a connection per machine. Plus: the multi-step connect modals now have a clear ← Back to the previous step, and Cancel exits the whole dialog (it used to quietly go back, which was confusing).
- Share machines on your edge bridge with another Cobblr workspace: pick which printers, choose read-only (watch) or read + write (control), and send a one-time link. Their workspace never receives your printer's credentials, and you can revoke access any time.
- External QR rules got simpler to set up and now cover every kind of label. Define a foreign system once: its base URL plus a list of `/segment/ → kind` children (e.g. `/printers/ → Machines`, `/parts/ → Parts`), and one rule handles a whole host: the segment picks the kind, the trailing id resolves the item. Works for machines, parts, assets, and locations alike, and the seeding backfill now covers all four.
- Groundwork for reading QR labels printed by other apps. The scanner can now be taught (per workspace) how to map a foreign QR code (a companion app URL, a bare Homebox number, …) to the matching Cobblr item, so labels you already printed keep working without a reprint. When a rule matches, the scan behaves exactly like a native one (opens the item). Opt-in and invisible until you set up a rule. The point-and-click setup lands next; today it's configurable via the API.
- The live Fleet view (machine status, temps, progress, in-flight jobs) is now a tab right inside your 3D Printers section. No more hunting for it under Configuration → Print Manager. It appears whenever the Print Manager is enabled, alongside the printer list. A linked printer's detail view also shows a live status chip (linked / connected / idle / printing % / needs-clearing / offline) so you can see state at a glance.
- The "that's a LAN address" warning in the direct-connect printer flow now only shows on a hosted Cobblr (cobblr.me / managed), which can't reach a device on your network. A self-hosted Cobblr on the same LAN no longer shows it: direct connection just works. Driven by a new `hosted` flag on `/auth/config`.
- A printer's photo is now editable from its detail modal. Hover the image and click Change to upload your own, Auto to re-fetch a product photo, or Remove. No more being stuck with whatever auto-loaded.
- The auto-fetched printer photo now appears live in the open detail modal: no need to close or refresh. When you open a printer with no image, Cobblr finds its product photo in the background and the thumbnail updates in place as soon as it lands.

### Fixes
- The Bambu live pump now derives the cloud MQTT username from the account token when the stored one is blank, so real-time telemetry starts even for connections saved before this, plus clearer pump logging.
- The Digital Fabrication entry in the navbar now opens its page instead of bouncing back to the workspace home: the page is routed at `/digifab` to match the nav link.
- Fixed an edge-bridge printer getting stuck on "loading…" with a dead Link button. The machine's host/key wasn't reaching the bridge (a config-shape bug), so a PrusaLink/Duet printer never appeared. Also: a direct driver (PrusaLink, Duet, LAN Bambu) IS the one printer, so its detail no longer shows a pointless "which printer" dropdown. It links directly. The dropdown now only appears for a true multi-printer farm manager (FDM Monster / OctoPrint).
- Connecting a printer by IP no longer creates a broken connection. Typing a bare address like `192.168.1.50` (no `http://`) now gets normalized to a proper URL instead of being saved schemeless, which previously surfaced later as "unreachable, invalid URL" in the fleet. An address that still can't be parsed is rejected up front with a clear message.

## 2026-06-19

### Features
- Connected printers now get a product photo automatically: you do nothing. When you add or open a 3D printer, Cobblr searches the web for its model (e.g. "Bambu Lab A1 3D printer"), fetches the best match into your file store, and sets it as the printer's image. Reuses the same image pipeline that gives a scanned product its photo; the image lives in your workspace, and any photo you upload yourself always wins.
- You can now connect a 3D printer to its print manager right from the printer flow: the "New 3D printer" modal has a Print Manager section (turn it on with one tap if it's off, then link to FDM Monster, OctoPrint, or Bambu), and the printer's own page has the connect panel. Workspaces that installed a machine bundle before this feature shipped get Print Manager turned on automatically: no reinstall.
- Connect a Bambu Lab printer by signing in with your Bambu account: no IP, no access code to copy. Add a connection → Bambu Lab, log in (region + email + password, with 2FA if you use it), and Cobblr discovers the printers on your account and pulls each one's details automatically. Cloud mode gives you live status in the fleet cockpit; the wizard tells you up front what each mode can and can't do (remote control needs LAN + Developer Mode, coming next).
- A machine type with its own tab (3D Printers, Laser Cutters, CNC Machines) now opens the full machine page. Set every field, edit, attach files, and link the machine straight to its print manager (FDM Monster/OctoPrint) from its own page, instead of a name-only stub. Installing one of those bundles also offers a checked-by-default "Connect to your machines" option that brings the Print Manager along.
- Setting up a tracker is smoother. The "what do you want to keep track of?" search now tolerates typos: *"pprint"* still finds 3D Printers, *"machne"* finds Machines. And picking a ready-made tracker no longer pops a second *"enable this module?"* dialog; Cobblr enables what the tracker needs and installs it in one step.
- Forward receipts by email. Every workspace you're in now has its own `receipts+…@` address (shown on the Scan page. Tap Copy). Forward a receipt there and its attachment runs through the same parser as an upload, landing as line items in that workspace's scan inbox, no app, no typing. The address itself names the workspace (signed, so it can't be typo'd or forged into someone else's), so multi-workspace folks get one address each and they all arrive in one inbox on our side. Operator-configured (needs the mail Worker set up, like reply-by-email); when it isn't, the address just doesn't show.
- Receipts now parse without AI whenever they can. Upload a CSV export or a text PDF with a line-item table and Cobblr pulls out the items deterministically: header-mapped columns for CSV, table extraction for PDFs, no model call, works even with no AI provider configured. A messy PDF falls back to a single AI text read, and a photo of a receipt still uses an AI vision read. Same one-row-per-line-item inbox triage either way; the inbox remembers how each line was read.
- A scanned or forwarded receipt can now become one purchase order instead of a pile of unrelated parts. With the Purchases module on, a receipt in your scan inbox shows a "Confirm as purchase order" banner: one tap creates a purchase order (vendor, date, total) and files every line as an order item linked to its part. You can still fix or discard individual lines first; it rolls up whatever's left. Without Purchases, the lines just confirm into parts as before.
- Public surfaces (wall panels) now have a per-surface auto-refresh setting and an E-paper mode. Pick how often a published screen re-fetches (every 30s up to hourly, or Off for a static panel) and flip on E-paper mode to force a light, high-contrast (black-on-white) layout with auto-refresh off, so a reflective panel in a cabinet doesn't ghost on a timer. Works for view, board, and whole-App surfaces.

### Improvements
- Connecting a Bambu printer now lives right in the New 3D printer flow: pick what kind of printer it is (Bambu, Klipper, Prusa, …) and how to connect: Directly through Bambu API or through a manager (FDM Monster / OctoPrint). Choosing Bambu-direct signs you into your Bambu account once, discovers every printer on it, and lets you pick which one this is, with the name and model pre-filled and the printer linked the moment you create it. One login covers your whole fleet.
- After a one-click bundle update, the dashboard row keeps a "See details" link (and shows the version you updated to), so you can still open the bundle and read what changed. The 3D Printers / Laser Cutters / CNC Machines bundles now carry that "what's new" note too.
- Creating a location while filling out a form no longer pops a second modal: "+ new location" now expands as an accordion right inside the form you're in. Kind is a two-button pick (Container / Area) instead of a dropdown, and a container you name "Bin" (or "Shelf", "Drawer") gets a globally-unique number appended automatically, "Bin 17", so every container has a unique label/scan number.
- The machine / 3D-printer detail modal opens without scrolling: a tighter header (photo + actions + Kind share the top row) and small add-pills: Tag · File · Link · Note. That only grow into full fields once you use them, instead of a wall of empty attachment boxes. Known printer models also show a product photo in place of the name-initial placeholder (drop images in `web/public/printers/`).
- A 3D printer's detail form now shows only the fields its kind needs. A Bambu (or Prusa) (a closed product where the vendor owns the hardware) hides the DIY build-detail block (hotend, extruder, mainboard, firmware, bed size, local IP); a Klipper / RepRap / Marlin printer you configured yourself still shows them. Quantity is gone from individual machines too (a printer is one unit, not a stock count). Existing Bambu printers clean up automatically; a Kind selector lets you adjust.
- The New 3D printer "what kind of printer is this?" picker now includes RepRapFirmware (Duet) alongside Bambu, Klipper, Prusa, and Marlin, so Duet owners pick their control ecosystem and connect through Duet Web Control.
- A machine's State is now a dropdown (functional / needs maintenance / broken / building / built / kit / rebuilding / loaned / sold / decommissioned) instead of a free-text box, with any existing value preserved. Also fixed the printer thumbnail: a broken image now falls back to the name-initial letter (no broken-image icon), and the auto-fetched product photo now lands correctly on printers that live in a named tab (e.g. 3D Printers).

## 2026-06-18

### Features
- Plug in a barcode scanner and just scan. USB or Bluetooth barcode scanners (1D laser or 2D imager) now work hands-free on the Scan page: point, pull the trigger, and the item lands in your inbox automatically. No need to open the UPC box or click into a field first. Typing into a real field still works normally, so the scanner never gets in the way.
- A brand-new workspace now starts with capture, not setup. Instead of a blank builder asking you to define modules and fields, the first screen asks "What do you want to keep track of?": just scan something or write something down ("3 skeins of blue worsted wool", "my Ender 3 printer"). Cobblr reads each thing against its ready-made trackers and, once a few cluster, offers to build the right one in a tap: "These look like yarn, make a Yarn tracker (3)" installs the tracker and files everything you captured into it, fields and all. No structure to design up front, do first, organise after.
- Track a consumable (a filament spool, a yarn cone, a roll of anything) properly. Set its capacity (the new 1kg), and Cobblr keeps a consumption ledger on the item: what drew it down and how much, each with its source, so you can see *"started at 1kg → these prints used this much → here's what's left."* A print that declares its filament writes a ledger row automatically (attributed to the print). The part page shows a remaining-vs-capacity gauge + the full history.
- Building a print farm from scratch? Digital Fabrication's new Add several button stands up a whole fleet at once: paste a list of printer URLs (one per line: `url`, or `name, url`, or `name, url, apikey`), pick a default firmware, and Cobblr makes one direct connection per printer, installs the drivers it needs, and (optionally) groups them all into a pool. Hit Detect firmware and it probes each URL to guess OctoPrint vs Klipper/Moonraker vs PrusaLink vs Duet for you. Tick test each to see which came up reachable. (Migrating an *existing* FDM Monster farm? Use Import farm instead.)
- The print farm got a real cockpit: live camera feeds, temperatures, and pause/resume. Each printer on the Fleet now shows its live nozzle and bed temperature, and you can give it a camera URL (your OctoPrint/Klipper webcam stream, or any MJPEG/HLS feed). Cobblr embeds the live feed right on the printer's card, so you can watch every machine from one screen. And a running print now has Pause and Resume controls (where the machine's manager supports it). Cobblr still never touches the camera or the hardware directly; it embeds the stream the manager already serves and asks the manager to pause; coordinate-not-control all the way down.
- A finished print no longer closes your task until you confirm it came out good. A printer reporting "completed" only means the gcode finished, not that a good part is on the bed (it could be spaghetti). So Cobblr now treats the after-effects by how much it hurts to get them wrong: your filament count and machine hours still update the moment a print finishes (cheap to undo), but closing the to-do that print was for now waits for your verdict. When you clear the bed, you tap Came out good: which closes the linked task, or Scrapped: which puts the filament and the machine usage back and leaves the task open. In the normal good case it's one tap you were already making; the one thing that used to silently go wrong on a failed print (a task marked done that wasn't) no longer can.
- Drive a printer at home from a Cobblr in the cloud: no port-forwarding. The print farm now supports the device tunnel: an edge agent on your network dials *out* to Cobblr and holds the connection open, so a hosted Cobblr can list, upload, print, pause, and track a printer behind home NAT exactly as if it were on the same LAN. Point a Digital Fabrication edge-adapter connection at `cobblr-edge://` and it routes through the tunnel instead of a direct URL. Two edge agents ship: the standalone edge-bridge (Docker/Pi) and a new OctoPrint plugin (`OctoPrint-Cobblr`) that also posts rich print updates, with a live webcam snapshot, straight to Discord. (It reuses the same proven dial-out path as Cobblr's local-AI relay. The cloud relay is hosted-only; self-hosted Cobblr on your LAN doesn't need any of this.)
- Print farm safety. The pool queue no longer auto-starts the next print on a printer that just finished: a finished (or failed) print now flags the printer "needs clearing" on the Fleet view, and the auto-assigner skips it until you tap Cleared, ready. No more crashing a fresh print onto a bed that still holds the last part. Two more hardening fixes ride along: a transient network blip while polling no longer flips a healthy in-progress print to "failed" (it retries a few times first), and a pool job whose send fails now shows up as failed with the reason instead of silently sitting "waiting" forever.
- Digital Fabrication now opens on a live Fleet view: every machine across all your connections on one floor, each with its current state (printing / idle / error / offline) and, when there's a Cobblr job on it, the file and a progress bar. A header counts the fleet at a glance ("12 machines · 4 printing · 1 error"). It refreshes itself, and an unreachable manager just flags its own row instead of blanking the rest. It reads what your machine managers (FDM Monster, OctoPrint, …) report. It never drives the hardware.
- Machines now accrue usage as your prints run. Link a print job to a machine, and each completed print bumps that machine's lifetime print count (and hours, when the manager reports a duration). It's the foundation for maintenance-by-usage: pair it with a maintenance threshold to get reminded "nozzle due at 500 prints" instead of guessing. Runs through a wire on print completion, so it's tunable like anything else.
- A print job can now declare the filament it consumes (a part + grams), and when the print finishes Cobblr deducts that material from your stock automatically. Your farm finally knows your filament. No more guessing whether you can start the next plate. (Set it on a new job under "Filament"; deduction runs through a wire on completion, so you can tune or disable it like any wire.)
- Digital Fabrication can now run a cross-machine queue. Make a pool (a set of machines, even across different connections) then queue jobs onto the pool instead of a single printer. Cobblr drips each job onto the next *free* machine as printers finish, so you can throw a batch at your farm and walk away. It's how you run a pile of individual printers (OctoPrint, Klipper, …) as one farm without FDM Monster in the middle. Pure coordinate-not-control: Cobblr only picks which printer gets the file.
- Live print updates in Discord, with the webcam snapshot, the ETA, and one post instead of two plugins. As a job runs, the farm posts to Discord (or in-app, or email): started → 25 / 50 / 75 % → finished / failed, as a rich, colour-coded card with Progress, Remaining, Elapsed, and Filament, the live webcam snapshot embedded right in the post, and a Live view link to the feed, the OctoEverywhere experience, in one message. Set it up once at Me → Notification channels: add `digifab.print.*` (or `*`) on the Discord channel with your server's webhook URL. The snapshot works wherever Cobblr can reach the camera (a self-hosted instance on the same network as the printer); everything else (the card, ETA, links) works everywhere. A failed print comes through as a red, high-priority alert.
- The print farm scales to a real fleet: searchable pickers + bulk actions. Every New-Job dropdown (connection, filament spool, pool, machine, printer) and the printer→machine link picker is now a type-to-search box instead of a scroll-through list, so picking the right spool out of a full inventory, or the right printer out of fifty, is a few keystrokes. The print queue got checkboxes: select a batch (or select-all) and Send / Cancel / Remove them in one click instead of confirming fifty times, a mixed selection only acts on the rows each action applies to. And building a pool is no longer one-dropdown-click-per-machine: + add machines… opens a searchable checklist so you add the whole set at once.
- Print queue: live, cancellable, and no longer capped. The queue now updates on its own while anything is running (no more stale snapshot: pool auto-assignment and print progress refresh live). Every job gets Cancel (tells the printer to stop where the manager supports it; otherwise marks it cancelled so Cobblr stops tracking it) and Remove from queue (a queued/finished job, an active print must be cancelled first so you can't lose track of it). And the queue no longer silently hides everything past 200 jobs: it pages, with a Load older jobs button and a status filter behind the API.
- Stuck print jobs can be re-pointed at a printer: no delete-and-recreate. When a job's target matches no printer (or several), it lands in *awaiting assignment* instead of guessing. Now each such job in the queue has a Pick printer button: choose one from a searchable list and it's sent straight there, reusing the file Cobblr already uploaded, so there's no re-upload and no rebuilding the job from scratch. Picking a printer that isn't on that connection is refused, so a stray pick can't misroute the print.
- See your printer's webcam from anywhere: opt-in snapshot relay (off by default). A printer's camera is usually a LAN-only address, so it only shows in the Fleet when you're on the same network. Turn on Relay snapshots to cloud (the camera control on a Fleet card) and the edge agent pushes a frame every few seconds up to Cobblr, which serves the latest back, so you get a near-live thumbnail of the printer from your phone, anywhere, without exposing your camera or streaming full video. It's off until you switch it on (it uses upload bandwidth), and the tunnel itself still carries only stats, not video. This is the deliberate, cheap middle ground for remote viewing. Paired with the OctoPrint plugin's matching "relay snapshots" toggle.
- Migrating off FDM Monster? Digital Fabrication now has an Import farm button. Point it at your FDM Monster and bring its printers in two ways, your choice: connect to each printer directly: Cobblr recreates every printer as its own connection of the *matching* type (OctoPrint, Klipper/Moonraker, PrusaLink, FluidNC: per printer, not all-OctoPrint), installs the drivers it needs, pools them, and drops FDM Monster from the path; or keep FDM Monster and mirror its printers into a Cobblr pool. Either way the Fleet reads the imported machines as one farm.
- Upload a receipt and Cobblr reads it for you. On the Scan page, hit Receipt, pick a receipt PDF or a photo of one, and AI pulls out the vendor, date, and every line item. Each lands in your scan inbox as its own row, ready to confirm into a part the same way a barcode or photo scan does. No more typing a receipt in by hand.
- Spoolman users: Cobblr now talks to it. Connect your Spoolman (Inventory → Spoolman) and Sync: each spool comes in as an item with its measured remaining weight, and Cobblr treats Spoolman as the source of truth: it mirrors the number and won't deduct that spool itself (so a print counted by Moonraker → Spoolman isn't double-counted). Don't use Spoolman? Nothing changes. Cobblr's own consumption ledger keeps tracking. The right tracker for your setup, automatically.

- Capture-first onboarding now works without AI. When a workspace has no AI provider (free tier, self-host, or offline), the matcher falls back to a deterministic keyword + field-overlap pass, so writing "3 skeins of blue worsted merino wool" still gets identified as Yarn (fiber Wool, weight Worsted, qty 3) and offers to build the tracker, at zero AI cost. Connecting an AI provider only sharpens the identification + field-fill; capture-first never goes dark.
- The Configuration page is no longer a wall. It now opens to the ~11 settings you actually use day-to-day, grouped and fully visible; the other two dozen (tokens, integrations, diagnostics, …) tuck behind a single Show advanced settings button. Search still finds every setting regardless. And Simple mode now does something visible: turning it on drops you straight onto your clean workspace home, and if you come back to Configuration it shows a calm one-card state instead of the control room, with one click to turn it back off.
- The print-farm cockpit now shows chamber temperature and the current job stage ("Preheating bed", "Calibrating extrusion", …) on each printer card, so you can see *why* a printer isn't printing yet, not just that it's busy. Surfaced by the edge-bridge's Bambu and new Klipper/Moonraker drivers.
- The Fleet floor now groups machines by pool: so a pool of individual printers (one OctoPrint here, a Klipper there) reads as one farm, with a header and a machine count, even across different connections. Machines that aren't in a pool still show under their connection. The payoff of running your printers as a Cobblr farm instead of through FDM Monster.
- Opening Cobblr on a new device (or any time there's no remembered workspace) now lands you on the top of your workspace switcher (your first owned workspace) instead of your oldest membership, which could be a shared workspace sitting low in the list. (A pin-your-own default workspace is a planned follow-up.)
- Managed apps (like Cobblr for Yarn) now show their tabs in a curated order (the headline tracker first) instead of alphabetically.
- The + New thing dialog now explains its two choices far more clearly. Each option leads with the key idea: *"Stands on its own"* vs *"Lives inside an existing thing"*, followed by when to pick it and a concrete example, so it's obvious whether you want a brand-new standalone list or a sub-category nested inside something you already track.
- The new-workspace start screen is now one page with no dead-ends: a single search box at the top: type "yarn", "3d printer", or just describe what you have ("blue worsted wool, 3 skeins"), that both filters the ready-made trackers below it AND lets you add freeform text directly (Cobblr finds the right tracker). The full tracker gallery shows inline (no more "Start from a template" that whisked you to a separate view with no way back), with the marketplace one link away.
- A photo you scan that can't be auto-identified (a bare photo on a workspace with no vision AI) no longer sits spinning forever. It now shows a one-field "What is this?" box; type a couple of words ("blue worsted yarn") and Cobblr routes it to the right table and fills the fields it recognizes, just like a written note. Works in both the Scan Inbox and the capture-first onboarding.

### Fixes
- The Fleet view stays fast and gentle on a big farm. The live floor used to ask every connected machine manager for its printer list on every refresh, all at once: fine for a couple of printers, rough at fifty, where one slow manager could stall the whole view. Now each connection's printer list is briefly cached (a rapid refresh or a second screen reuses it), each fetch is time-boxed (a slow or unreachable manager falls back to its last-known state instead of freezing everyone), and the fetches run in bounded batches rather than a fifty-wide burst. Your in-flight jobs, links, and bed-clear flags are still read live every refresh, only the printer *state* can be a few seconds old.
- Print jobs honour printer tags on every farm, and won't land on the wrong machine. A job targeted at a tag (e.g. your "PLA" group) now resolves to a real printer inside Cobblr before it's sent, so it works the same on every connected farm, including FDM Monster's classic submit, which used to ignore the tag and let the farm route the file wherever it liked. And if a job points at a printer that isn't on its connection (a stale or mixed-up id), the send is refused with a clear error and the job is left in the queue to re-target, instead of silently printing on whatever machine happened to share that id.
