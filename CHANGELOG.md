# Changelog

User-facing changes, newest first. Dates are release dates.

## 2026-06-23

### Features
- Duet printers get a full control panel. The Duet driver now exposes Home, a 3-axis Jog, and Nozzle/Bed set-temp (not just pause/resume/stop), so a Duet on the edge bridge has the same rich modal controls as a Bambu. Ships via the embedded bridge bundle; bridges self-update.
- Duet printers: full controls, your macros as buttons, and print-from-SD. The Duet modal now has live tuning (speed/flow), baby-step Z, chamber temp, part-fan % + LED toggle, a button for every macro on the printer (LED on/off, bed presets, etc.), and a Print button on each file in the list to start an on-SD file without re-uploading.
- Sort the printer file list + see upload dates. Each gcode file now shows when it was put on the printer, and the list can be sorted by Newest / Oldest / Name / Largest.
- Printer modal: live print progress + per-file estimates. When a printer is mid-print the modal now shows a progress bar with % / current layer / time-left / elapsed. In the file list, tap any file to see its slicer estimate (print time, filament length, layer count, height) fetched once and cached.
- Gcode previews in the printer file list. Files sliced with an embedded thumbnail (PrusaSlicer/Orca/SuperSlicer) now show that preview right in the list: same image DWC renders. Previews load lazily as you scroll and are cached, so the printer isn't hammered. Click one to enlarge.
- When a barcode resolves to a thin entry (a bare category like "Bourbon" from a crowdsourced food-facts mirror, missing the brand), the scan now uses web + AI to build the full product title ("Bulleit Bourbon Frontier Whiskey 750mL") and writes the richer result back to the shared Barcode Intelligence DB, so it supersedes the thin entry for every future scan. External databases are a starting point; we enrich our own on first encounter.
- Klipper printers get the full cockpit. Klipper/Moonraker machines now report live job progress, list their on-disk gcode files with slicer thumbnails and print-time/filament estimates, run from storage, and expose the complete control set: speed/flow, home/jog/baby-step, temps, part fan, and every one of your Klipper macros as a button.
- See the files already on a printer. The device modal now lists the gcode files on the printer's own storage (Duet via the edge bridge). It's cached (5-minute server cache, fetched once in the UI, never polled) with a manual Refresh: so a fairly-static list doesn't hammer the printer.
- Edit a Scan Rule as JSON. The rule edit/new modal gets a Form / JSON toggle: flip to JSON to tweak the raw rule and flip back, with the form and JSON kept in sync. Pairs with the Paste JSON button for create.
- QR labels can now encode a self-describing URL: `/qr/<kind>/<id>` instead of an opaque random token. The win: a scanned code stays meaningful even if this Cobblr instance is ever gone or moved (you can read what it points at straight off the URL, and it survives route changes), where an opaque token is a dead pointer without the database. It's the new default; flip a workspace to opaque (shorter, reveals nothing, scans better on tiny labels) on the QR codes page. Both styles resolve identically and anything you've already printed keeps working.
- New green "This is good: lock it in" button on a scanned barcode item: when the listing is correct, one tap verifies its name, brand, category and photo into the shared barcode database, so every future scan of that code, in any workspace, gets your clean entry instead of a thin crowdsourced one. It doesn't re-run the AI or commit to inventory; it just locks the data in.
- The scanned-item correction buttons are now a pair, half-width each: "Right: needs detail" (the product is correct but the listing is sparse, keep the identity, re-check every source + the web to fill in the proper name, size and photo) and "This is wrong" (re-derive the product from scratch). Both steer off your optional note and push the result back to the shared barcode database.
- The source-data panel on a scanned item now shows a short history of what you did to it: "Asked for more detail · 2 min ago", "Flagged wrong", "Locked into the barcode database", newest first, so you can see what's already been tried. The correction buttons are also reordered into traffic-light order: red This is wrong → yellow Right, needs detail → green This is good, lock it in.
- The scan card gets a proper image viewer: tap the catalog or your-photo image to view it full-size, "Revert to original" to undo a photo pick and restore the image the lookup first gave, and "Use my photo" to make your own scan the catalog image. The original is preserved server-side, so revert works even after a reload.
- Create a Scan Rule by pasting JSON. The External QR Rules page gets a Paste JSON button. Drop in a rule's `{name, match, resolve}` and it's created, instead of filling out the form field by field. Handy when someone hands you a ready-made rule.
- Scans now group into visible "sessions." Whatever you scan with a hardware scanner (or the camera) flows into one session until you idle for 30 minutes, then a fresh session starts. The inbox shows these as collapsible groups with a time, location, and count header ("Today 2:48 PM · Garage · 6 items"), so you can finally see how your scans are batched, and a "New session" button starts a fresh group on demand.
- New "This is wrong: re-check everything & fix it" button on a scanned item. One press re-queries every source (go-upc, upcitemdb, Open Facts) plus a web search, steered by your optional "what's wrong" note, distrusts the flagged listing, reconciles the correct name + photo, and pushes the correction back to the shared barcode database so the next scan (anyone's) is right. The source panel now also shows when the listing was last updated ("10 min ago"). "Re-run AI" is unchanged.
- You can now keep a live link to another system. Add a *sync connection* (the first is companion app), and its records mirror straight into your workspace: connect it once, and e.g. every room, rack, and bin you add in companion app shows up as a Cobblr location, hierarchy and all. It's a real connector, not a one-off: changes arrive instantly via webhook, with a periodic reconcile that backstops anything missed and removes things deleted at the source. Credentials are encrypted at rest, and the same machinery is built to host more connectors over time.
- Sync connectors now do a proper one-time import preview before they touch anything. Enabling an entity type (e.g. companion app locations) no longer writes straight to your workspace. You pull a dry-run plan that shows exactly what *would* happen (create / merge-into-existing / update / unchanged / remove), eyeball it, and approve. The first import even merges a source record into a same-name item you already have instead of duplicating it. Once you approve, that entity type switches to live sync (webhook + poll). Live pushes and the background poll stay withheld until the import is approved.
- Search the web for a printer's photo. The 3D-printer / machine modal now has a "search the web for a photo" strip. Pick a product shot and it becomes the printer's image. It's the same picker the scan inbox uses, now a shared component available anywhere an item needs a photo.

### Improvements
- Connecting a print manager from a printer is now one step. Opening "Connect one" from a printer jumps straight to the edge-bridge machine form (no type-picking), pre-fills the machine name from the printer, and pre-selects the driver from the printer's kind (Klipper/Prusa/Duet).
- Printer file lists & previews are now served from a durable backend cache. A background warmer keeps each printer's file list and gcode thumbnails fresh in the database, so opening a printer is instant and never pulls from the machine itself: the printer is touched only on the backend's schedule, and each thumbnail is fetched exactly once.
- Printer files & previews are cached harder. The file list is cached 15 min and each thumbnail 30 min, on both the server and in the browser, so reopening a printer is instant and the printer itself is touched at most once per window, never on every modal open.
- Printer/asset location pickers now show rooms in your order. The location dropdown for printers and machines lists only areas (rooms/zones, not bins) in your arranged order with natural sorting (Bin 1, 2, … 10, not 1, 10, 2). And you can connect a print manager after the fact: the printer's Print Manager panel now has an inline "Connect one" / "+ new" that sets up a manager without leaving the page.
- The top navigation bar now spans the full width of your window instead of being boxed into a centred ~1150px column, so the module nav gets the whole row before links fold into the "more ▾" menu. Page content (tables, forms, lists) stays centred at a comfortable reading width.

### Fixes
- Newly-connected print manager auto-selects. After "+ new" creates a manager from a printer, it's now selected in the dropdown (with its printer auto-picked) instead of dropping back to "choose…", so you can Link immediately.
- Duet printers report live temps. The edge-bridge Duet driver now reads bed/chamber/nozzle temperatures (from `rr_status?type=2`), so a Duet on the local bridge shows live telemetry like the others. Ships via the embedded bridge bundle: bridges self-update automatically.
- Live temps in the printer modal for edge-bridge machines. The device-detail telemetry was Bambu-cloud only, so a Duet / PrusaLink / Moonraker printer connected through the local edge bridge showed no live telemetry in its modal. It now pulls live temps + state from the bridge's device list when there's no Bambu cloud report.
- Thin-hit enrichment now captures the spec, not fluff: when a barcode resolves to a bare name and we enrich from the web, the result keeps the package size / quantity (1.75 L, 750 mL, 12 ct, proof) that identifies the SKU, and only replaces the thin name when it actually adds the size or the brand: never just longer marketing wording.
- Scan catalog images are far more accurate for store/own-brand products. The image search now includes the brand in the query (not just the ranking), so a generic name like "Blended Scotch Whiskey" + brand "Kirkland Signature" no longer comes back as a random Johnnie Walker bottle. The brand is skipped when the title already contains it, so the query is never duplicated.
- Scan matchmaker suggestions come back much faster. The AI now only writes an explanatory note when something actually needed reconciling (a title-vs-photo disagreement, an inferred field, an unconfirmed pack count) and omits it for a clean match, instead of always composing a 2–4 sentence paragraph. Typical routing dropped from ~18s to ~5s with no loss of useful explanations.
- Scan cards no longer show a broken-image icon when a catalog photo URL is dead. If the main catalog image fails to load it falls back to the server-cached copy or your own photo; and any "other photo options" thumbnail that won't load is dropped from the strip instead of showing a broken tile.
- Re-scanning a barcode now always merges into the one pending item you already have, no matter which scanning session you're in, and moves it into the current session. Previously dedup was scoped per session, so re-scanning the same code in a new session created a duplicate (and the original looked like it had gone missing).
- The scan inbox now groups un-batched items by day (Today / Yesterday / date) instead of lumping them all under one "No session" header. Explicit scanner sessions still show as their own timed group; everything else reads as coherent day buckets, newest first, so the list makes sense even for items scanned before sessions existed.
- The scan item's research-hint box is now a full-width, multi-line field so its placeholder is no longer cut off (Enter submits, Shift+Enter adds a newline). And the enlarged-image viewer now shows the "other photo options" strip along the bottom, so you can swap to a different photo without leaving the zoom: picking one swaps the big image in place.
- For items identified by web search (e.g. books), the cleaned-up name the AI describes is now actually used as the item name, so the note ("publisher and author stripped from name") matches what you see, instead of the header still showing the raw "Publisher Title (Author)". Sizes/specs are never dropped, and database-identified products are unaffected.
- Scan names now lead with the brand when a sparse source name leaves it off: "Black Label No.7" (Jack Daniel's) becomes "Jack Daniel's Black Label No.7". Names that already include the brand are left as-is.
- Re-scanning a barcode that's already in your inbox, or restoring one from the deleted section, now brings it back to the TOP of the queue instead of leaving it buried at its original position. Previously a re-scan or restore updated the item in place far down the list, so it looked like the scan did nothing and the item had gone missing.
- The scan card's "Source data" panel (provenance + the fields it routed to) is now expanded by default instead of collapsed.
- When a barcode isn't in any database and we fall back to a web search, the AI now picks the product that most search results agree on, instead of occasionally latching onto a single obscure or accessory listing ("Customers also bought…", "Related…"). Pairs with the earlier fix that feeds it real product-page titles.
- Scan items can no longer get stuck spinning on "finding the best table…" forever. If the matchmaker step ever failed (e.g. a slow/timed-out AI call) it left no completion stamp, so the card spun indefinitely with no way to recover. Now the matchmaker records completion even on failure, and the card gives up the pulse after a few minutes, showing the identified item so you can route it by hand.

## 2026-06-22

### Features
- Import & export locations as CSV. On the Locations page, Export downloads your whole location tree, and Import lets you paste/upload a CSV and preview the exact create/update/skip diff (and any unresolved parents) before anything writes. Generic: pick which column matches existing locations, set parent by that same column, and any extra columns are kept on the location's metadata, so you can round-trip another system's ids.
- Locations now has a navbar entry. Previously the rooms/places tree was only reachable under Configuration; it's a top-level Locations item now: per-device show/hide/reorder like any other nav entry, so the place tree is one click away.
- Order your locations by hand. Each location now has up/down arrows to set the display order within its group (rooms in the order you want, rather than alphabetical). The order persists and applies everywhere the tree renders; un-ordered groups stay alphabetical.
- Rename the Locations nav entry to your word. The top-level Locations entry now honors the org-wide display-name override (Configuration → Presentation): call it "Rooms", "Areas", whatever fits your workspace, consistent on every device.
- Locations: unsorted containers get their own section + natural sort. Loose containers (bins not placed in any room/area) now sit in a separate "Unsorted containers" section at the bottom, so the room/area tree stays clean. Names also sort naturally: Bin 1, Bin 2, … Bin 10, Bin 11 (not Bin 1, Bin 10, Bin 2).
- Select-all + bulk delete on Locations. A Select all button (and a Delete action in the selection bar) lets you clear out locations in one pass: handy for re-importing a corrected CSV. Deleting a parent cascades to its children.
- When a scanned barcode finds nothing in the catalogs or on the web but you snapped a photo, the item is now named from the photo instead of being left blank. The AI already reads the photo to describe and sort the item. Now it turns that read into an actual title (e.g. a museum-gift souvenir box, a foreign-language book edition the catalogs miss), so you get a usable name to confirm rather than an empty "name required" field.
- When you add a photo to a scan whose barcode came back wrong, the photo now wins. A barcode/web search can return a spurious listing (a debug probe coming back as a "power supply"); if your photo unambiguously shows a different product, the item is now renamed to what the photo shows: the old wrong title is dropped, the photo-derived details become the ones to work from, and the corrected barcode→name is reported back to the shared barcode database so the next scan is right. (Previously this check only ran for direct barcode hits, not web-search results, so a wrong web-search title would stick.)
- Book and music scans now resolve from the local mirrors. A scanned book's ISBN-13 is an EAN barcode, so it's now looked up through the shared barcode database (which now holds the Open Library catalog): instant, offline, no per-scan call to Open Library's API; a brand-new book not yet mirrored still falls back to the live API. CDs/vinyl already went through that path, so they pick up the new MusicBrainz music data automatically. Provenance reads "Open Library" / "MusicBrainz".
- Bulk-triage gained Set location: tick a batch of scans and file them all into one place in a single step (it appears in the selection toolbar next to Confirm/Discard whenever your workspace has locations). Pairs with the filing context: scan a pile anywhere, select them, and drop them into "Garage Shelf 3" at once.
- Bulk-triage the inbox. Tick a few scans (or "select all") and a toolbar lets you Confirm or Discard the whole selection at once. No more one-by-one. Confirm sends each item to its own best table match with the fields the matchmaker already extracted; anything without a confident match is left in place for a quick manual look, and the summary tells you how many landed. Turns a 30-scan session into one tap to file.
- New URLs intake on the scan page: paste a list of product links (one per line, up to 50) and each becomes an inbox item, identified in the background through the same web-lookup the camera uses for a scanned URL. Handy for cataloging an online order or a wishlist when there's no barcode to scan. Drop the links in, and they fill in names/photos/categories on their own.
- Scanning now has a filing location ("active bin"). Set "Filing into → {location}" on the Scan page (or pick an area in the camera), and every scan: hardware gun, UPC, or camera, is filed into that location, persisting on the item so even a later triage already knows where it was scanned and pre-fills it. Confirming files the new item into that location in your `core-locations` tree. It's the warehouse "put-away" pattern: choose where you're standing once, then just scan; the location rides along instead of being re-picked per item.
- Barcodes that the lookup services can't find now get a little more help. Every barcode's prefix encodes the country where it was registered (a Prusament filament barcode starts 859 = Czech Republic), and the AI identifier now gets that as a hint, so when web results are thin it can still make a better guess at the maker. Free and instant, no extra lookup.
- The scan inbox now has a "⚠ N needs review" filter. After you bulk-confirm the confident scans, flip it on to show only the ones that didn't cleanly resolve: no name yet, a short/ambiguous barcode, a rate-limit retry, or low confidence, so you focus your attention exactly where it's needed instead of scrolling the whole pile. Bulk-select respects the filter, so "select all" + Confirm/Discard acts on just the shown set.
- When you scan an item and the barcode resolves to the wrong product, snapping a photo now gives you a one-tap fix. The photo cross-check already noticed the mismatch; now it also reads the real product off the label and offers a "Use photo's name: …" button. One tap renames the item to what the photo shows, and reports the correction to the shared barcode database, so the next person who scans that code gets the right name automatically.
- Re-scanning an item to add a photo now improves the entry you already have instead of making a second one. When a barcode came back with the wrong (or no) name, scanning it again with the camera attaches that photo to the existing entry (even from a later session) and re-checks the name against the photo, so the "this doesn't look right" flag (and the one-tap fix) appear on the row you were already looking at. No more duplicate rows for the same thing.
- Two scan clean-ups. Clearer provenance: when a barcode resolves instantly from the shared Barcode Intelligence DB (its cache or the grocery mirror) the note now reads "BIdb / go-upc" instead of a bare "go-upc", so an instant hit no longer looks like a live lookup it couldn't have been. Better English names from web search: the fallback that names an item from web results now prefers English titles over foreign-market listings (it was only filtering non-Latin scripts, so French/Spanish names slipped through), fewer "pâte à tartiner" names when an English one is available.
- Scan a location to start filing into it: zero clicks. Print a QR label for a room/shelf/bin (any `core-locations` place), and scanning it makes it the active filing bin: everything you scan next files in there. Scan a container while a room is active and it *nests*, the container is filed into the room and becomes the new bin (so "scan the garage, scan the tote, scan the parts" lands the parts in the tote, the tote in the garage). Scanning another area just switches context (it won't wrongly nest one room inside another), and a move that would create a loop is skipped. Works the same from the camera and a hardware scan gun.

### Fixes
- Bambu connection messaging now reflects hybrid LAN+cloud. LAN and hybrid modes are marked available (they shipped), the capability notes describe what each mode actually does, and the connection badge says "cloud · monitor + light/pause" vs "lan/hybrid · full control" instead of a blanket "control". Stale "coming soon / Phase 3 / no remote control" copy removed.
- Personal/BYO AI (the edge bridge) is more reliable under a flaky agent connection. The agent that carries your AI long-polls the cloud, and in the brief gaps between polls a request could hit "no edge device connected" and fail, which made the scan matchmaker fall back to "Matched by keywords (no AI)" even though AI was connected. Those momentary disconnects are now retried (a few seconds, with backoff) so the call waits for the agent's next poll instead of giving up.
- Scan catalog pictures are more reliable: the image search now retries when DuckDuckGo's image endpoint returns empty (it's flaky from a server IP even when the web search has results), and re-running AI on an item now re-fetches its picture by name, so a barcode whose title was corrected upstream but whose image stayed wrong (e.g. a "Pinecil" showing a ribbon cable) fixes itself on re-run.
- Locations: clearer area icon. The "area" kind icon was a plain square that looked like a second, unchecked checkbox next to the real select checkbox. It's now a location pin. No more double-checkbox confusion.
- When AI isn't doing the matching, the inbox no longer force-fits an item into the wrong bundle. The keyword matcher used to suggest any table that shared a single word, so a "Pine64 LCD Ribbon Cable" got tagged Yarn (because "ribbon" is a yarn word). Now a table is only suggested when the item actually *is* that kind of thing (its noun matches) or a specific attribute matches, otherwise the card just offers the generic "Inventory part." Fewer, better chips (at most two), and no more cables in the yarn bin.
- When an item gets renamed: whether you fix it yourself or the photo correction replaces a wrong barcode title, the catalog picture now updates to match the new name instead of keeping the old product's image. (Previously a corrected name like "Pinecil Soldering Tip Set" could still show the wrong barcode's ribbon-cable photo.)
- Scanning a big batch no longer drops items to a raw, uncleaned name or a scary "502" note. The AI bridge that names and sorts each scan is a single agent, and a burst of scans used to overwhelm it, so some items kept the messy web-title ("… - Botland - Robotic Shop") instead of the tidy name the AI would have produced. Scans now queue gently to the bridge (a few at a time) and retry a momentary overload, so far more items come back with a clean AI name. Also: junk "inventory checker / price tracker" pages (BrickSeek, camelcamelcamel, bare UPC-lookup results) are no longer mistaken for the product name.
- The scan inbox now fits a phone screen. The intake buttons (UPC / URLs / Upload / Receipt / camera) sit in a strip that scrolls sideways instead of overflowing off the edge, so adding new intake options later can't break the bar again. And the per-item "which table" chips no longer stack into a tall wall on mobile: each card shows just the best match plus a "+N" you can tap to see the rest, while desktop still shows them all.
- A scanned physical product no longer gets suggested for admin tables it can't belong to. Scanning a barcode (or a photo the AI reads as an item) will never route to Subscriptions, Warranties, Documents, or Bills: those are records you add by hand, not by scanning. Scannable physical tables like Medications and Collections are unaffected. The guard is deterministic, so it holds even when AI is slow or offline.
- Three inbox fixes. Undo on remove: removing a scan (one or a whole selection) now shows an "Undo" button right on the toast, so a mis-tap is one click to put back instead of a trip to Recently deleted. Right words for a barcode: an item that's just a barcode (no photo) no longer says "Couldn't identify this photo". It says "barcode". No more stuck "Awaiting lookup": when a barcode lookup is rate-limited and the automatic retries are used up (e.g. the daily lookup quota is spent), the item now settles into a clear "couldn't identify, name it" with the name box ready, instead of spinning "retrying…" forever or sitting on a misleading "Awaiting lookup…".
- The "Removed: Undo" toast now names what you removed (the item's name, or its barcode) instead of a bare "Removed.", so a stack of them is easy to tell apart, and they auto-dismiss after a few seconds instead of piling up until you dismiss each one.
- The barcode web-search no longer "gives up" before the AI has answered. On a self-hosted or personal AI connection that's slow (100s+ per call), the web-search identify was timing out at 20 seconds and reporting "nothing found": even though the AI was still working and would have identified the item. The timeout is now generous enough (matching the matchmaker) for a slow model to finish, so far fewer scans fall through to "fill in manually" just because the AI was slow.
- Barcodes that aren't in any database now resolve far more often. The web-search fallback used to ask DuckDuckGo's image index for a name (which can't resolve a bare UPC) so it usually came up blank. It now asks the text/web search too, which returns the actual product pages (e.g. a Cuisinart pan's UPC → "Cuisinart Chef's Classic Nonstick Hard Anodized 11″ Square Griddle"), giving the AI real titles to identify from.

## 2026-06-21

### Features
- Barcode lookups now learn from your triage. When you confirm a scanned item after fixing its name, because the barcode lookup was wrong or found nothing, Cobblr quietly feeds that correction back to the shared barcode database, so the next scan of that product (in any workspace) gets your fix. It's invisible and never affects your own item; only a meaningful rename is sent, tagged anonymously. (Operator-configured via the resolver correction token; off until set.)
- Operators can now review barcode corrections from a public approval queue. When an instance is set to *propose* mode, user fixes to wrong/missing barcode lookups land in Super-admin → Barcodes → "Proposed corrections" with the current value vs the proposed one: Approve makes it the verified answer every workspace's next scan sees, Reject drops it. Approval uses a server-side review token (super-admin only; never exposed to public users), so a public instance can both capture proposals and host the review without handing out write access.
- Scanned items now get a cleaner catalog photo. Image options are ranked by catalog quality: a retailer or brand product page (clean studio shot on white) floats to the top, while recipe blogs, Pinterest, and styled/social photos sink, so the good photo is the first one you see instead of buried at #6. The barcode lookup's own auto-chosen image uses the same ranking. And when you pick a better photo for a scanned product, that choice is fed back to the shared barcode database as an image correction, so the next scan of that product (in any workspace) gets your clean image, beating whatever the providers had.
- Bambu LAN, as a setting on the printer. Open a Bambu printer in digifab → LAN access → enter its IP + access code, and Cobblr adds a LAN transport to the *same* printer (no second connection). Cloud keeps doing live telemetry; file-push (sending an arbitrary sliced file, which cloud can't do) and control now route through your on-site edge bridge over the printer's LAN. (Live camera over LAN is a follow-up; it needs an RTSP update in the bridge.)
- Printers connected through the edge bridge (Duet, Klipper/Moonraker, Prusa) now show live controls: Pause / Resume / Stop: in the printer modal, instead of "no live controls." Prusa printers also report their nozzle/bed temperatures now.
- Live camera over LAN. A Bambu printer with LAN access now shows its chamber camera right in the printer modal: a refreshing still, grabbed frame-by-frame over your bridge (cloud can't do this). Click it to zoom full-screen.
- New file library for digifab: upload your sliced .3mf / .gcode files and Cobblr pulls out the slicer's plate thumbnail for an at-a-glance grid (no slicer or render step: the preview is read straight from the file). Send any library file to a printer or a pool in one click. Multi-plate 3MFs show their plate count.
- A workspace can now run more than one edge bridge: a second site/VLAN, or LightBurn, which has to run its bridge on the LightBurn PC itself. Give the extra bridge an id in the connection setup; it gets its own tunnel channel and the machines you add are pinned to it. Your existing single bridge keeps working exactly as before (no id = the default channel).
- 3D-printer Print updates: post a photo + live status to Discord as a print runs: your rules. Add a Discord channel once, then make rules per printer (or all printers): post every N % / N minutes / N layers (whichever comes first, with an optional "no more than once every N min" cap), with a `{{param}}` message template you can preview, and the live camera photo attached.
- Click a printer in digifab (its name, or "Details & controls") to open a full printer modal: image, live telemetry (nozzle/bed/chamber temps, AMS filament colors + remaining, chamber light, firmware-update + alert badges), the controls (now inside the modal), a link-to-machine picker, and that printer's recent prints. Click any print: there or in the history list, for a detail card with a large cover you can click to zoom full-screen. The temperature controls show the live actual → target and pre-fill from the current target.
- Print queue gains priority and auto-reprint-on-fail. Mark a job High or Urgent and it jumps ahead of Normal jobs when a printer frees up; set an auto-retry count and a failed print re-queues and re-sends itself (pool jobs re-drip to any free printer, device jobs retry on the same one) instead of just stopping.
- Duplicate a print-update rule: a copy button on each rule clones it (cadence, message, hooks and all), so you can spin up a per-printer variant in seconds instead of rebuilding it.
- Print-update rules gain a "Test fire now" button (posts a real update from the printer's current live telemetry, so you can verify a rule end-to-end without waiting), plus pre/post hooks: run printer controls around the post (e.g. chamber light on → settle → shoot the photo → light off). Hooks run non-blocking, so the delays never hold up telemetry.
- Each Bambu printer now has a transport mode in its LAN-access panel: All cloud (status/control/history via Bambu's cloud), Prefer LAN (status + control + file-push over your bridge, cloud fills in print-history names), or LAN only (everything local, cloud off: no internet needed, but you lose cloud-only history names/covers). Cobblr pulls live telemetry over LAN for the LAN modes, so status keeps flowing even with the printer off the cloud.
- Scanning is now type-aware. No more guessing whether you can start the next plate. (Set it on a new job under "Filament"; deduction runs through a wire on completion, so you can tune or disable it like any wire.)
- Digital Fabrication can now run a cross-machine queue. Make a pool (a set of machines, even across different connections) then queue jobs onto the pool instead of a single printer. Cobblr drips each job onto the next *free* machine as printers finish, so you can throw a batch at your farm and walk away. It's how you run a pile of individual printers (OctoPrint, Klipper, …) as one farm without FDM Monster in the middle. Pure coordinate-not-control: Cobblr only picks which printer gets the file.
- Live print updates in Discord, with the webcam snapshot, the ETA, and one post instead of two plugins. As a job runs, the farm posts to Discord (or in-app, or email): started → 25 / 50 / 75 % → finished / failed, as a rich, colour-coded card with Progress, Remaining, Elapsed, and Filament, the live webcam snapshot embedded right in the post, and a Live view link to the feed, the OctoEverywhere experience, in one message. Set it up once at Me → Notification channels: add `digifab.print.*` (or `*`) on the Discord channel with your server's webhook URL. The snapshot works wherever Cobblr can reach the camera (a self-hosted instance on the same network as the printer); everything else (the card, ETA, links) works everywhere. A failed print comes through as a red, high-priority alert.
- The print farm scales to a real fleet: searchable pickers + bulk actions. Every New-Job dropdown (connection, filament spool, pool, machine, printer) and the printer→machine link picker is now a type-to-search box instead of a scroll-through list, so picking the right spool out of a full inventory, or the right printer out of fifty, is a few keystrokes. The print queue got checkboxes: select a batch (or select-all) and Send / Cancel / Remove them in one click instead of confirming fifty times, a mixed selection only acts on the rows each action applies to. And building a pool is no longer one-dropdown-click-per-machine: + add machines… opens a searchable checklist so you add the whole set at once.
- Print queue: live, cancellable, and no longer capped. The queue now updates on its own while anything is running (no more stale snapshot: pool auto-assignment and print progress refresh live). Every job gets Cancel (tells the printer to stop where the manager supports it; otherwise marks it cancelled so Cobblr stops tracking it) and Remove from queue (a queued/finished job, an active print must be cancelled first so you can't lose track of it). And the queue no longer silently hides everything past 200 jobs: it pages, with a Load older jobs button and a status filter behind the API.
- Stuck print jobs can be re-pointed at a printer: no delete-and-recreate. When a job's target matches no printer (or several), it lands in *awaiting assignment* instead of guessing. Now each such job in the queue has a Pick printer button: choose one from a searchable list and it's sent straight there, reusing the file Cobblr already uploaded, so there's no re-upload and no rebuilding the job from scratch. Picking a printer that isn't on that connection is refused, so a stray pick can't misroute the print.
- See your printer's webcam from anywhere: opt-in snapshot relay (off by default). A printer's camera is usually a LAN-only address, so it only shows in the Fleet when you're on the same network. Turn on Relay snapshots to cloud (the camera control on a Fleet card) and the edge agent pushes a frame every few seconds up to Cobblr, which serves the latest back, so you get a near-live thumbnail of the printer from your phone, anywhere, without exposing your camera or streaming full video. It's off until you switch it on (it uses upload bandwidth), and the tunnel itself still carries only stats, not video. This is the deliberate, cheap middle ground for remote viewing. Paired with the OctoPrint plugin's matching "relay snapshots" toggle.
- Migrating off FDM Monster? Digital Fabrication now has an Import farm button. Point it at your FDM Monster and bring its printers in two ways, your choice: connect to each printer directly: Cobblr recreates every printer as its own connection of the *matching* type (OctoPrint, Klipper/Moonraker, PrusaLink, FluidNC: per printer, not all-OctoPrint), installs the drivers it needs, pools them, and drops FDM Monster from the path; or keep FDM Monster and mirror its printers into a Cobblr pool. Either way the Fleet reads the imported machines as one farm.
- Upload a receipt and Cobblr reads it for you. On the Scan page, hit Receipt, pick a receipt PDF or a photo of one, and AI pulls out the vendor, date, and every line item. Each lands in your scan inbox as its own row, ready to confirm into a part the same way a barcode or photo scan does. No more typing a receipt in by hand.
- Spoolman users: Cobblr now talks to it. Connect your Spoolman (Inventory → Spoolman) and Sync: each spool comes in as an item with its measured remaining weight, and Cobblr treats Spoolman as the source of truth: it mirrors the number and won't deduct that spool itself (so a print counted by Moonraker → Spoolman isn't double-counted). Don't use Spoolman? Nothing changes. Cobblr's own consumption ledger keeps tracking. The right tracker for your setup, automatically.

### Fixes
- The Fleet view stays fast and gentle on a big farm. The live floor used to ask every connected machine manager for its printer list on every refresh, all at once: fine for a couple of printers, rough at fifty, where one slow manager could stall the whole view. Now each connection's printer list is briefly cached (a rapid refresh or a second screen reuses it), each fetch is time-boxed (a slow or unreachable manager falls back to its last-known state instead of freezing everyone), and the fetches run in bounded batches rather than a fifty-wide burst. Your in-flight jobs, links, and bed-clear flags are still read live every refresh, only the printer *state* can be a few seconds old.
- Print jobs honour printer tags on every farm, and won't land on the wrong machine. A job targeted at a tag (e.g. your "PLA" group) now resolves to a real printer inside Cobblr before it's sent, so it works the same on every connected farm, including FDM Monster's classic submit, which used to ignore the tag and let the farm route the file wherever it liked. And if a job points at a printer that isn't on its connection (a stale or mixed-up id), the send is refused with a clear error and the job is left in the queue to re-target, instead of silently printing on whatever machine happened to share that id.
